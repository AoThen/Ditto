## 简介

### 什么是 Ditto 云端同步？

Ditto 云端同步是一项扩展功能，允许您在多台设备之间实时同步剪贴板历史记录。通过安全的云端服务，您可以：

- ✅ 在办公室电脑和家里电脑之间同步剪贴板
- ✅ 通过 Web 浏览器查看和管理所有剪贴板历史
- ✅ 端到端加密保护您的敏感数据
- ✅ 多设备实时同步，无需手动操作

### 架构概述

```
┌─────────────┐         ┌──────────────┐         ┌─────────────┐
│  Ditto 客户端 │  HTTPS  │   Go 云端服务  │  HTTPS  │  Web 管理面板  │
│  (多设备)     │◄───────►│   (REST+WS)   │◄───────►│  (浏览器)     │
└─────────────┘         └──────────────┘         └─────────────┘
                               │
                        ┌──────┴──────┐
                        │  SQLite DB  │
                        │  (加密存储)  │
                        └─────────────┘
```

### 核心特性

| 特性 | 说明 |
|------|------|
| **统一仓库** | 所有设备共享同一份数据，`source_device_id` 仅用于标记来源 |
| **实时同步** | WebSocket 推送，新剪贴板自动同步到所有设备 |
| **端到端加密** | AES-256-GCM，云端无法解密，保护用户隐私 |
| **增量同步** | 仅同步变更，节省带宽和时间 |
| **冲突解决** | LWW (Last Write Wins) + CRC 去重 |
| **文件同步策略** | 文件类型只同步路径，不同步内容（保护隐私） |
| **OCR 图片识别** | 自动识别剪贴板图片中的文字，支持批量处理 |
| **拼音搜索** | 支持中文拼音首字母搜索剪贴板内容 |
| **单条不同步** | 可将指定剪贴板标记为不同步，保留本地 |
| **强制同步** | 手动触发强制上传/下载，覆盖数据 |
| **调试日志** | 可将同步日志写入文件，便于排查问题 |

## 快速开始

### 前置要求

1. **Ditto 客户端** - v3.25 或更高版本（已集成云端同步功能）
2. **云端服务** - Go 后端服务已部署并可访问
3. **网络连接** - 客户端能访问云端服务（HTTPS）

### 第一步：获取账号

Ditto 云端服务已关闭公开注册，账号由管理员统一创建：

1. 联系您的管理员，提供您的**用户名**和**邮箱**
2. 管理员创建账号后，您会收到初始密码
3. 打开 Ditto，右键系统托盘图标 → **选项**
4. 在左侧导航栏选择 **云端同步**
5. 填写以下信息：
   - **服务器地址**: 您的云端服务地址（例如：`https://cloud.example.com`）
   - **用户名**: 管理员为您创建的用户名
   - **密码**: 管理员提供的初始密码
6. 点击 **登录** 按钮（登录后可在Web面板修改密码）

### 第二步：登录

1. 使用刚才注册的用户名和密码登录
2. 登录成功后，状态会显示"已登录 (设备: device-XXX)"
3. 系统会自动生成设备 Token 并保存到注册表

### 第三步：启用云端同步

1. 勾选 **启用云端同步** 复选框
2. 勾选 **复制时同步新剪贴项** 复选框（推荐，默认开启）
3. 勾选 **定期同步** 复选框（推荐，默认开启），间隔保持默认 30 秒
4. 点击 **应用** 按钮
5. Ditto 会开始后台同步（按设定的间隔，默认 30 秒）

### 第四步：验证同步

1. 复制一些文本内容
2. 打开 Web 管理面板（浏览器访问云端服务地址）
3. 在"剪贴板"页面，您应该能看到刚才复制的内容
4. 在另一台设备上登录同一个账号，剪贴板会自动同步

## 功能详解

### 云端同步设置界面

#### 基本配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| **启用云端同步** | 开启/关闭云端同步功能 | 关闭 |
| **服务器地址** | 云端服务的 HTTPS 地址 | `https://localhost:8080` |
| **用户名** | 您的登录用户名 | - |
| **密码** | 您的登录密码 | - |

> 同步的具体模式（复制时同步新剪贴项 / 定期同步 / 间隔）见下方"同步模式配置"。

#### 状态显示

- **未登录**: 尚未登录或 Token 已清除
- **已登录 (设备: device-XXX)**: 已成功登录，显示设备标识
- **正在登录...**: 正在连接服务器
- **登录失败: [错误信息]**: 登录失败的具体原因

#### 同步模式配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| **复制时同步新剪贴项** | 复制新内容后立即推送到云端，而不是等待定期同步 | 开启 |
| **定期同步** | 后台定期从云端拉取其他设备的变更 | 开启 |
| **同步间隔** | 定期同步的间隔时间（5-300 秒） | 30 秒 |

**复制时同步新剪贴项（Push on Copy）**：当您复制新内容时，Ditto 会立即通过快速推送线程将新剪贴板推送到云端，其他设备几乎实时可见。此选项默认开启，建议保持开启。

**定期同步（Periodic Sync）**：后台线程按设定的间隔定期从云端拉取变更。如果关闭此选项，Ditto 将仅通过推送方式同步（即只有您复制新内容时才会触发同步，不会自动拉取其他设备的变更）。

**同步间隔**：在 5-300 秒之间调整，默认 30 秒。缩短间隔可提高同步实时性，但会增加网络请求次数。

#### 单条剪贴板不同步

您可以将特定剪贴板条目标记为"不同步"，使其保留在本地，不会上传到云端，也不会被其他设备看到。

**设置方法**：

1. 在 Ditto 剪贴板列表中，右键点击目标条目
2. 选择 **不同步此剪贴板**（菜单项会根据当前状态显示为勾选/取消）
3. 该条目会显示不同步标记，云端同步时会跳过它

**其他方式**：

- **编辑属性**：选中条目后按 `Ctrl+E` 或右键 → **属性**，在对话框中勾选 **不同步**
- **批量操作**：选中多条后，在右键菜单中批量设置不同步
- **分组管理**：在分组树中右键点击分组，选择 **标记为不同步**，该分组下的所有条目都将被标记

**取消不同步**：重复上述操作即可取消标记，后续同步会将该条目上传到云端。

**跨设备效果**：
- 标记为不同步的条目仅存在于本地设备
- 其他设备不会看到该条目
- 如果从 Web 面板将某条标记为不同步，所有设备都会跳过该条

#### 强制同步

在特殊情况下（如首次启用、数据不一致、更换设备后），您可以使用强制同步功能。

| 操作 | 说明 | 行为 |
|------|------|------|
| **强制下载** | 用云端数据覆盖本地 | 从云端拉取所有剪贴板数据，替换本地数据 |
| **强制上传** | 用本地数据覆盖云端 | 将本地所有剪贴板推送到云端，替换云端数据 |

**使用场景**：

- **强制下载**：新设备首次同步时，希望拉取云端所有历史数据；或者本地数据损坏，需要从云端恢复
- **强制上传**：更换设备后，希望将旧设备的数据推送到新账号；或者本地数据比云端更完整

**注意事项**：
- 强制同步会覆盖目标端的数据，操作前请确认方向正确
- 强制同步完成后，正常增量同步会继续生效
- 强制同步是异步操作，点击按钮后会在后台执行，可通过同步状态查看进度

#### OCR 图片文字识别

Ditto 可以自动识别剪贴板图片中的文字，将识别结果添加到剪贴板描述中，方便搜索和查找。

**启用 OCR**：

1. 在云端同步设置页面，勾选 **为图片启用 OCR**
2. 点击 **应用** 保存设置
3. 此后复制图片时，Ditto 会自动识别图片中的文字

**强制重新运行 OCR**：

如果之前复制的图片没有 OCR 结果，或者更新了 OCR 引擎，可以点击 **强制重新运行 OCR** 按钮，对所有历史图片重新执行文字识别。

**工作原理**：
- 复制图片时，Ditto 在后台将图片数据发送给 OCR 引擎
- 识别出的文字会添加到剪贴板的 `m_Description` 字段
- 该描述会同步到云端，其他设备搜索时也能命中
- 如果图片已经有文字格式（如 CF_UNICODETEXT），则跳过 OCR（避免重复处理）

**注意事项**：
- OCR 识别是异步的，文字可能在复制后几秒才出现
- 识别结果的质量取决于图片清晰度和文字排版
- 强制重新运行 OCR 时，界面会显示进度提示

#### 拼音搜索索引重建

Ditto 支持中文拼音搜索，您可以通过拼音首字母快速查找剪贴板内容。

**使用场景**：当您发现拼音搜索不准确或新建了大量剪贴板后，可以重建拼音索引。

**重建方法**：
1. 在云端同步设置页面，点击 **重建拼音索引** 按钮
2. 确认操作后，Ditto 会遍历所有剪贴板条目
3. 为每条记录生成拼音和拼音首字母索引
4. 完成后显示处理条目数

**默认行为**：新复制的条目会自动生成拼音索引，无需手动重建。仅在以下情况需要重建：
- 从旧版本升级（之前没有拼音索引）
- 导入的外部数据没有拼音索引
- 数据损坏导致索引丢失

#### 调试日志

Ditto 提供调试日志功能，帮助排查云端同步问题。

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| **将调试日志写入文件** | 将调试信息写入日志文件（`debug.log`） | 关闭 |
| **记录剪贴板内容** | 在日志中记录剪贴板数据的详细内容（可能暴露敏感数据） | 关闭 |

**日志查看方法**：

1. **使用 DebugView（推荐）**：
   - 下载 [DebugView](https://docs.microsoft.com/en-us/sysinternals/downloads/debugview)
   - 以管理员身份运行
   - 筛选 `[CloudSync]` 关键字
   - 执行操作，观察日志输出

2. **启用日志文件**：
   - 勾选"将调试日志写入文件"后，Ditto 会将日志写入 `%APPDATA%\Ditto\debug.log`
   - 适合长时间记录，事后分析

**安全提示**：
- 启用"记录剪贴板内容"后，日志中会包含剪贴板数据的明文内容
- 排查完毕后请关闭此选项，避免敏感信息泄露
- 分享日志前请检查是否包含敏感信息

### 同步行为说明

#### 推送（Push）

当您在本地复制新内容时：

1. Ditto 监控到剪贴板变化
2. 保存到本地 SQLite 数据库
3. 触发 `OnClipAdded()` 事件
4. 快速推送线程启动，将新剪贴板推送到云端
5. 云端接收后，通过 WebSocket 通知其他设备

**推送内容**：
- ✅ 文本（CF_TEXT, CF_UNICODETEXT）
- ✅ HTML（CF_HTML）
- ✅ 图片（CF_DIB, CF_BITMAP）- base64 编码
- ✅ 富文本（Rich Text Format）
- ⚠️ 文件（CF_HDROP）- **只同步路径，不同步文件内容**

#### 拉取（Pull）

后台同步线程按设定的间隔（默认 30 秒）检查一次云端变更：

1. 发送 `since` 时间戳到云端
2. 云端返回自上次同步以来的所有变更
3. 解密格式数据（如果启用了加密）
4. 合并到本地数据库（CRC 去重）
5. 更新 `lastSyncTime` 并持久化到注册表

#### 冲突解决

| 场景 | 处理策略 |
|------|---------|
| CRC 相同 | 跳过（视为同一条） |
| 同一远程 ID 内容不同 | 服务端最后写入优先 (LWW) |
| 删除冲突 | 软删除优先（tombstone） |

### 文件类型同步策略

**重要**: 文件剪贴板（`CF_HDROP`）**只同步路径，不同步文件内容**。

**原因**：
1. 文件可能极大（几GB视频/压缩包）
2. 路径是机器相关的（`C:\Users\Alice\report.pdf` 在B电脑不存在）
3. 与 Ditto 现有设计一致（文件内容本来就是按需拉取）
4. 保护隐私（文件可能含敏感数据）

**效果**：

| 端 | 能看到什么 |
|----|-----------|
| Web 端 | "复制了文件 report.pdf"，但无法下载文件 |
| 设备 B | 能看到文件记录，但路径可能无效 |
| 本地 | 文件剪贴板正常使用，完全不受影响 |

## 端到端加密

### 加密概述

Ditto 云端同步使用**端到端加密**保护您的剪贴板数据：

- **加密算法**: AES-256-GCM
- **密钥派生**: PBKDF2-HMAC-SHA256（10 万轮）
- **Salt 管理**: 服务端生成并存储，确保多设备使用同一 salt
- **云端视角**: 只存储密文，无法解密

### 启用加密

#### 方法一：设置加密密码

1. 在"云端同步"设置页面，找到"端到端加密"区域
2. 输入您的**加密密码**（建议强度高、易记忆的密码）
3. 点击 **启用加密** 按钮
4. 系统会：
   - 从云端获取 salt
   - 使用 PBKDF2 派生 AES 密钥
   - 将密钥保存到注册表（不可逆）
   - 初始化加密模块
5. 成功后显示"加密已启用 (Salt: xxx...)"
6. 点击 **测试加密** 验证加密是否正常工作

#### 方法二：导入密钥文件

如果您在其他设备上已经启用了加密：

1. 点击 **导入密钥** 按钮
2. 选择 `.dittokey` 文件
3. 输入导出时设置的密码
4. 导入成功后，加密自动启用

### 加密工作流程

```
┌──────────────────────────────────────────────────────────────┐
│                      端到端加密流程                             │
│                                                              │
│  推送剪贴板（设备 A）                                           │
│    剪贴板数据 ──► AES-256-GCM 加密 ──► 密文 ──► HTTPS ──► 云端│
│                                                              │
│  拉取剪贴板（设备 B）                                           │
│    云端密文 ──► HTTPS ──► AES-256-GCM 解密 ──► 明文展示       │
│                                                              │
│  云端视角                                                      │
│    存储的 data 字段 = AES-256-GCM 密文                          │
│    服务端无法解密，用户隐私得到保护                              │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### ⚠️ 重要警告

**忘记密码 = 数据不可恢复！**

- 云端只存储密文，无法帮您重置密码
- 每个新设备都需要输入加密密码或导入密钥文件
- **强烈建议**导出密钥文件并妥善保管

### 加密密码变更处理

如果某台设备修改了加密密码，其他已登录设备需要重新验证密码才能继续同步。

**触发场景**：
- 在 Web 管理面板或客户端修改了端到端加密密码
- 其他设备在同步时检测到密码已变更

**处理流程**：

1. 当另一台设备检测到密码变更时，会弹出提示框：
   > "加密密码已在其他设备上变更，请输入新的加密密码以继续同步。"
2. 在弹出的对话框中输入新的加密密码
3. 系统会向云端验证新密码，验证通过后自动更新本地密钥
4. 同步自动恢复

**注意事项**：
- 如果输入错误密码，会提示验证失败，可重新输入
- 多次失败不会锁定设备，但无法同步数据
- 如果忘记了新密码，需要在这台设备上导入密钥文件

### 加密密钥丢失恢复

在某些情况下，加密密钥（DEK）可能丢失或损坏，导致无法解密数据。

**触发原因**：
- 注册表被清理或重置
- 更换 Windows 用户账户
- 系统还原后注册表项丢失
- 手动删除了注册表中的加密密钥

**检测机制**：Ditto 启动时检测到加密密钥缺失，会：
1. 停止云端同步（防止数据丢失）
2. 在注册表中标记"需要恢复"
3. 弹出恢复提示框

**恢复流程**：

1. 当您看到"加密密钥丢失或损坏"的提示时，选择 **是** 进入恢复流程
2. 在云端同步设置页面，重新设置加密密码：
   - 输入新的加密密码
   - 点击 **启用加密**
   - 系统会从云端获取 salt，重新派生密钥
3. 恢复后，正常同步自动恢复

**重要提示**：
- 恢复后，之前已加密的云端数据将无法解密（因为使用旧密钥加密）
- 这些旧数据会被跳过，不会影响同步流程
- 恢复后新推送的数据将使用新密钥加密
- 如果之前在另一台设备上保留着密钥文件，可以导入密钥文件恢复，而无需重新设置密码

## 密钥文件管理

### 为什么需要密钥文件？

密钥文件是加密密码的备份，允许您在不知道密码原文的情况下导入加密密钥。

**使用场景**：
- 在新设备上登录，但不想输入加密密码
- 忘记密码，但保留了密钥文件
- 团队成员共享加密密钥

### 导出密钥文件

1. 确保加密已启用（"加密状态"显示"加密已启用"）
2. 点击 **导出密钥** 按钮
3. 输入密码保护密钥文件（此密码用于加密导出的密钥文件）
4. 选择保存位置（建议保存到 U 盘或安全位置）
5. 文件名为 `ditto-cloud.dittokey`
6. 导出成功后，路径会显示在"密钥文件路径"输入框中

**导出内容**：
```json
{
  "version": 1,
  "username": "your_username",
  "created_at": "2026-04-12T10:30:00Z",
  "salt": "<base64编码的salt>",
  "encrypted_key": "<base64编码的加密密钥>",
  "checksum": "<base64编码的校验和>"
}
```

### 导入密钥文件

1. 点击 **导入密钥** 按钮
2. 选择 `.dittokey` 文件
3. 查看密钥文件信息（用户名、创建时间）
4. 输入导出时设置的密码
5. 导入成功后，加密自动启用

### 密钥文件安全

**⚠️ 重要提示**：
- 密钥文件包含完整的加密密钥
- **切勿**通过邮件、聊天等方式分享给他人
- 建议存储在加密的 U 盘或密码管理器中
- 如果密钥文件泄露，任何持有该文件的人都可以解密您的剪贴板数据

## 故障排除

### 登录失败

**问题**: 点击登录后显示"登录失败: [错误信息]"

**可能原因**：
1. **服务器地址错误** - 检查 URL 是否正确（包括 `https://` 前缀）
2. **网络连接问题** - 检查是否能 ping 通服务器
3. **用户名或密码错误** - 确认凭据正确
4. **服务器未启动** - 联系管理员确认服务状态

**解决方案**：
```
1. 检查服务器地址是否正确
2. 在浏览器中访问服务器地址，确认服务可访问
3. 确认用户名和密码（注意大小写）
4. 查看 Ditto 输出日志（OutputDebugString）
```

### 同步不工作

**问题**: 勾选了"启用云端同步"，但剪贴板没有同步

**排查步骤**：

1. **检查登录状态**
   - 状态应显示"已登录 (设备: device-XXX)"
   - 如果显示"未登录"，请先登录

2. **检查同步模式**
   - 确认"复制时同步新剪贴项"已勾选（否则只有定期同步才会推送）
   - 确认"定期同步"已勾选（否则不会自动拉取远程变更）
   - 同步间隔建议 30 秒或更短

3. **检查单条不同步标记**
   - 右键点击未同步的条目，检查是否被标记为"不同步"
   - 被标记的条目不会上传到云端

4. **查看日志**
   - 使用 DebugView (Sysinternals) 查看日志
   - 搜索 `[CloudSync]` 关键字
   - 正常日志应显示：
     ```
     [CloudSync] 2026-04-12 10:30:00 Background sync thread started.
     [CloudSync] 2026-04-12 10:30:30 PushNewClips: checking for new/modified clips...
     [CloudSync] 2026-04-12 10:30:30 PushNewClips: 1 clips synced, 0 skipped
     ```

5. **检查加密状态**
   - 如果加密启用但密钥不正确，同步会失败
   - 点击"测试加密"验证加密是否正常

6. **尝试强制同步**
   - 点击"强制下载"或"强制上传"按钮
   - 观察同步状态是否更新

### 加密失败

**问题**: 点击"启用加密"后显示错误

**可能原因**：
1. **无法获取 salt** - 网络连接问题或服务器未响应
2. **密码为空** - 必须先输入加密密码
3. **salt 大小不正确** - 服务端返回的 salt 应为 32 字节

**解决方案**：
```
1. 确认已登录（获取 salt 需要认证）
2. 输入加密密码（至少 4 个字符）
3. 检查服务器是否正常
4. 查看日志获取详细错误信息
```

### 密钥文件导入失败

**问题**: 导入密钥文件时显示"密码可能不正确"

**可能原因**：
1. **密码错误** - 输入的密码与导出时不一致
2. **文件损坏** - 密钥文件在传输过程中损坏
3. **版本不兼容** - 密钥文件版本与当前客户端不兼容

**解决方案**：
```
1. 确认密码正确（注意大小写）
2. 检查密钥文件完整性（文件大小、JSON 格式）
3. 确认密钥文件版本为 1
4. 重新导出密钥文件（如果可能）
```

### 文件同步问题

**问题**: 复制文件后，其他设备看不到文件

**说明**: 这是**预期行为**。文件类型（`CF_HDROP`）只同步路径，不同步内容。

**效果**：
- Web 端能看到"复制了文件 XXX"的记录
- 其他设备能看到文件路径，但路径可能无效（因为路径是源设备的）
- 本地文件剪贴板正常使用，不受影响

### OCR 识别失败

**问题**: 启用了 OCR 但图片没有识别结果

**可能原因**：
1. **图片质量差** - 模糊、反光、文字过小的图片难以识别
2. **图片已有文字格式** - 如果图片包含 CF_UNICODETEXT 格式，会跳过 OCR
3. **OCR 引擎未初始化** - 首次启用后需要重启 Ditto
4. **图片格式不支持** - 仅支持 CF_DIB 和 PNG 格式

**解决方案**：
1. 确认在设置中勾选了"为图片启用 OCR"
2. 点击"强制重新运行 OCR"对所有历史图片重新识别
3. 检查 DebugView 日志中的 `[OCR]` 关键字输出
4. 重启 Ditto 后重试

### 拼音搜索不准确

**问题**: 拼音搜索无法找到预期的剪贴板

**可能原因**：
1. **拼音索引未生成** - 旧版本升级后索引缺失
2. **索引过期** - 大量新增剪贴板后索引未更新
3. **数据损坏** - 索引数据损坏

**解决方案**：
1. 在设置页面点击"重建拼音索引"按钮
2. 重建完成后重试搜索
3. 如果问题持续，检查日志中是否有数据库错误

### 强制同步无效

**问题**: 点击强制上传/下载后没有变化

**可能原因**：
1. **同步未完成** - 强制同步是异步操作，需要等待几秒
2. **Token 已过期** - 检查登录状态，重新登录
3. **网络问题** - 检查与服务器的连接

**解决方案**：
1. 等待 10-15 秒，观察同步状态更新
2. 重新登录后重试
3. 使用 DebugView 查看 [CloudSync] 日志确认操作是否触发

### 加密密码变更后无法同步

**问题**: 收到"加密密码已变更"提示后，输入新密码仍无法同步

**可能原因**：
1. **密码输入错误** - 新密码与云端设置不一致
2. **网络问题** - 无法连接服务器验证密码
3. **Token 已过期** - 需要先重新登录

**解决方案**：
1. 确认输入的密码与 Web 面板或其他设备上设置的密码一致
2. 检查登录状态，如已过期请重新登录
3. 如果仍然失败，尝试导入密钥文件恢复

## 常见问题 (FAQ)

### Q: 我可以同时在多少台设备上使用？

A: 理论上没有限制。所有设备登录同一个账号后，会共享同一份剪贴板数据。

### Q: 如果一台设备删除了某条剪贴板，其他设备会怎样？

A: 删除是全局的。一个设备删除某条剪贴板后，所有设备都不可见（软删除）。

### Q: 我忘记了加密密码，怎么办？

A: **很遗憾，数据将无法恢复。** 云端只存储密文，无法帮您重置密码。这就是为什么强烈建议导出密钥文件。

### Q: 可以在没有网络的环境下使用吗？

A: 可以。Ditto 的本地功能完全不受影响。云端同步只是扩展功能，断开网络后本地剪贴板管理照常工作。

### Q: 同步会消耗很多流量吗？

A: 不会。Ditto 使用增量同步，只同步变更。文本剪贴板通常只有几 KB，图片可能几十到几百 KB。

### Q: 支持 macOS 或 Linux 吗？

A: 当前版本仅支持 Windows（Ditto 本身是 Windows 应用）。Web 管理面板可以在任何操作系统上使用浏览器访问。

### Q: 如何备份我的剪贴板数据？

A: 有两种方式：
1. **本地备份**: Ditto 本地数据库在 `%APPDATA%\Ditto\Ditto.db`，直接拷贝即可
2. **云端备份**: 云端服务会定期备份数据库（具体取决于您的服务提供商）

### Q: Token 有效期是多久？

A: 客户端保存的设备 Token（JWT Access Token）默认有效期为 **30 天**（可由管理员通过 `JWT_ACCESS_TOKEN_EXPIRY` 配置调整）。Token 过期后，客户端会收到 401 响应并弹出重新登录提示。Web 面板使用独立的 Refresh Token（默认 90 天）自动续期，不受此影响。

### Q: 如何撤销某个设备的访问权限？

A: 在 Web 管理面板的"设备管理"页面，找到要移除的设备，点击"移除设备"。该设备的 Token 会立即失效。

### Q: 如何让某些敏感剪贴板不同步到云端？

A: 右键点击该剪贴板，选择 **不同步此剪贴板**。该条目会保留在本地，不会上传到云端。也可在 Web 面板选中后点击"标记不同步"。

### Q: OCR 识别结果会同步到云端吗？

A: 会。OCR 识别出的文字会写入剪贴板描述（`m_Description`），并随剪贴板一起同步到云端，方便其他设备搜索。

### Q: 强制下载会覆盖我本地的数据吗？

A: 会。**强制下载**会用云端数据覆盖本地数据；**强制上传**会用本地数据覆盖云端数据。请在使用前确认方向，避免数据丢失。

### Q: 不同步的剪贴板在本地还能正常使用吗？

A: 可以。标记为"不同步"仅影响云端同步，本地剪贴板功能（复制、粘贴、搜索）完全不受影响。

### Q: 我的登录凭据是如何存储的？

A: Ditto 使用 Windows DPAPI 加密保护设备 Token 和本地凭据，仅当前 Windows 用户可解密。即使注册表被导出，也无法在其他机器上使用。

## 安全建议

### 密码安全

1. **登录密码**: 至少 8 位，建议包含大小写字母、数字、符号
2. **加密密码**: 强度应更高，建议 12 位以上
3. **不要使用相同密码**: 登录密码和加密密码应不同

### 密钥文件安全

1. **存储在安全位置**: U 盘、密码管理器、加密文件夹
2. **不要通过网络传输**: 邮件、聊天工具等都会留下记录
3. **定期检查**: 确认密钥文件未被篡改
4. **及时销毁**: 不再需要时，安全删除（覆盖写入后删除）

### 设备安全

1. **不要共享设备**: 每个设备应有独立的设备 Token
2. **及时移除不用的设备**: 在 Web 端移除旧设备
3. **监控设备列表**: 定期检查是否有未知设备

### 网络安全

1. **使用 HTTPS**: 确保服务器地址是 `https://` 开头
2. **验证证书**: 如果是自签名证书，确认指纹是否正确
3. **不要使用公共 Wi-Fi**: 公共网络更容易被中间人攻击

### 数据隐私

1. **敏感数据加密**: 如果经常复制密码、银行卡号等，务必启用端到端加密
2. **定期清理**: 设置自动清理规则，删除过期的剪贴板
3. **审查同步内容**: 注意哪些内容会被同步到云端

## 附录

### 注册表位置

Ditto 云端同步配置存储在注册表：

```
HKEY_CURRENT_USER\Software\Ditto\
  ├── CloudServerUrl             (字符串) - 服务器地址
  ├── CloudDeviceToken           (字符串) - 设备 Token（DPAPI 加密）
  ├── CloudDeviceId              (字符串) - 设备 ID
  ├── CloudSyncEnabled           (DWORD)  - 是否启用同步
  ├── CloudPushOnCopy            (DWORD)  - 复制时同步新剪贴项
  ├── CloudPeriodicSync          (DWORD)  - 定期同步
  ├── CloudSyncInterval          (DWORD)  - 同步间隔(秒, 5-300)
  ├── CloudEncryptionKey         (字符串) - 加密密钥 (Base64)
  ├── CloudEncryptionSalt        (字符串) - 加密 Salt (Base64)
  ├── CloudEncryptionNeedsRecovery (DWORD) - 加密密钥需要恢复标记
  ├── CloudLastSyncTime          (字符串) - 最后同步时间 (Unix 时间戳)
  ├── CloudKeyFilePath           (字符串) - 密钥文件路径
  ├── CloudLastUsername          (字符串) - 上次登录用户名
  ├── Cloud\EnableOCR            (DWORD)  - 为图片启用 OCR
  ├── EnableDebugLogging         (DWORD)  - 将调试日志写入文件
  ├── LogClipboardContent        (DWORD)  - 记录剪贴板内容
  └── EnableOutputDebugStringLogging (DWORD) - 写入 OutputDebugString
```

### 凭据安全

Ditto 使用 **Windows DPAPI（Data Protection API）** 保护设备 Token 和本地凭据：

- **DPAPI 加密**：Token 写入注册表前使用当前 Windows 用户凭据加密
- **用户隔离**：仅加密该 Token 的 Windows 用户可解密，其他用户无法使用
- **防导出攻击**：即使导出注册表文件，在其他机器上也**无法解密** Token
- **透明使用**：客户端读取时自动解密，用户无感知

### 日志查看

使用 **DebugView** (Sysinternals 工具) 查看实时日志：

1. 下载 DebugView: https://docs.microsoft.com/en-us/sysinternals/downloads/debugview
2. 以管理员身份运行
3. 筛选 `[CloudSync]` 关键字
4. 执行操作，观察日志输出
